# Полная инструкция

## Структура проекта

| Папка | Назначение |
|-------|------------|
| `src/` | Интерфейс: React и TypeScript |

## Windows

### Установщик

[Releases](https://github.com/NeyroslopInzh/inzh-work-calendar/releases) → `inzh.work.calendar_*_x64-setup.exe`.

`x64` — обычный 64-битный процессор, Intel или AMD. На ARM установщик не запустится.

### Исходники / сборка

Нужны Node.js и Rust.

```powershell
npm install
npm run tauri build
```

Готовый установщик появится в `src-tauri/target/release/bundle/nsis/`.

## Linux

### Требования к сборке

WebKitGTK 4.1 и библиотеки Tauri:

```sh
sudo apt-get update
sudo apt-get install -y libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf
npm install
npm run tauri build
```

`.deb` — в `src-tauri/target/release/bundle/deb/`, AppImage — в `src-tauri/target/release/bundle/appimage/`.

### Готовые файлы

```bash
sudo apt install ./inzh.work.calendar_*_amd64.deb
```

```bash
chmod +x inzh.work.calendar_*_amd64.AppImage
./inzh.work.calendar_*_amd64.AppImage
```

`amd64` — тот же 64-битный процессор, что и `x64`. На ARM бинарник не запустится.

Если AppImage пишет, что не хватает FUSE, поставь `libfuse2`.

## Окно и трей

Закрытие окна прячет календарь в трей. Левый клик по значку или пункт «Открыть» возвращает окно. Выход — пункт «Выход». При первом запуске включается автозапуск; его можно выключить в шапке окна. Рядом переключается тёмная и светлая тема.

## Задачи

| Поле | Смысл |
|------|--------|
| Название | Обязательно |
| Описание | Необязательно |
| Начало | Необязательно. Напоминание только в статусе «К выполнению» |
| Дедлайн | Необязательно. Напоминает, пока задача не в «Готово» |
| Повтор | Дни недели в диапазоне дат, не длиннее трёх лет |
| Статус | «К выполнению», «В работе», «Готово» или свой, между первыми двумя и «Готово» |

Напоминание приходит не чаще раза в 10 минут. Если дедлайн уже прошёл, напоминание о начале замолкает: стучит только дедлайн. Отложить можно на 15 минут, час, 3 часа, сутки или своё число минут, но не больше суток.

Карточку можно перетащить на другой день или в другую колонку. «К выполнению» и «Готово» убрать нельзя. Если удалить свой статус, его задачи возвращаются в «К выполнению».

Дни повтора: 1 — понедельник … 7 — воскресенье. В выбранном диапазоне должен попасть хотя бы один такой день.

## Локальный вход задач

Приложение слушает только `127.0.0.1`. Порт берётся из `47321`–`47330` и записывается в `endpoint.json` вместе с токеном.

Каждый запрос требует заголовок `Authorization: Bearer {token}`.

| Запрос | Действие |
|--------|----------|
| `GET {base}/health` | `{ "ok": true }` |
| `GET {base}/tasks` | Список задач |
| `POST {base}/tasks` | Создать |
| `PATCH {base}/tasks/{id}` | Изменить. `null` снимает дату или повтор |
| `DELETE {base}/tasks/{id}` | Удалить |

Пример создания:

```json
{
  "title": "помыться",
  "description": "",
  "startAt": "2026-11-13T21:00",
  "deadlineAt": "2026-11-14T09:00",
  "status": "todo",
  "recurrence": {
    "from": "2026-11-13",
    "until": "2026-12-13",
    "weekdays": [1, 3, 5]
  }
}
```

Время — местное `YYYY-MM-DDTHH:MM`, `YYYY-MM-DD HH:MM`, `YYYY-MM-DDTHH:MM:SS` или RFC3339. `startAt`, `deadlineAt`, `description` и `recurrence` можно не передавать. `status` по умолчанию — `todo`.

Если приложение выключено, допиши одну JSON-строку в `inbox.jsonl` в том же каталоге. При запуске календарь заберёт файл. Битая строка останется в `inbox.failed.jsonl`, остальные применятся.

## Частые случаи

### Окно «закрылось», а процесс жив

Так и задумано: приложение в трее. Выход — «Выход» в меню значка.

### Локальный адрес не открылся

Порты `47321`–`47330` заняты. Пока приложение запущено, `endpoint.json` не обновится. Задачу можно дописать в `inbox.jsonl`.

### На ARM не стартует

В релизе только `amd64` / `x64`.

### AppImage не запускается

Часто не хватает FUSE. Поставь `libfuse2` и запусти файл снова.
